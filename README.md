# Awesome Multi-Agent Orchestrators [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

> An awesome-style, selectively curated list of open-source and publicly documented multi-agent orchestrators, coding-agent workspaces, agent runtimes, company operating systems, and adjacent governance layers.

[Website](https://openorchestrators.org/) • [Contributing](./CONTRIBUTING.md)

The public website is [Open Orchestrators](https://openorchestrators.org/). This repo is intentionally narrow: it is not a general AI tools list. Projects belong here when multi-agent coordination, parallel agent execution, agent workflows, or agent-centered operating systems are the product, not a side feature. Governance and enforcement layers are tracked separately when they control agent actions, permissions, approvals, budgets, trust, settlement, or audit trails without acting as the orchestrator itself.

## Latest Additions

- [Aixle Flow](https://aixle.com/labs/flow) ([GitHub](https://github.com/AixleHQ/flow), [Docs](https://github.com/AixleHQ/flow/tree/develop/docs)) - Apache-2.0 self-hosted Kanban board where moving a card starts a durable Temporal workflow; each step runs Claude Code, Codex, Cursor CLI, Gemini CLI or another CLI agent in its own container, with approval gates and per-run token and cost tracking.
- [Sno Station](https://www.sno.ai/) ([GitHub](https://github.com/sno-ai/sno-station), [Install](https://github.com/sno-ai/sno-station#install)) - Apache-2.0 local layer that turns Codex, Claude Code, Cursor, Hermes Agent and OpenClaw on one computer into a squad: when one agent hits its rate limit, another picks up the task from the same memory and mailbox with context intact, and either agent can review the other's work, with the reviewer always a different agent. Memory is encrypted locally, and messages and skills live on the machine; no daemon or server is needed. A nightly Self Learning job proposes skill changes that apply only after the user accepts them. Linux and macOS. REM Enhanced sends memory text to Sno's cloud; Agent Native uploads sessions nightly for Self Learning by default unless disabled, while Local First does not upload memory text.
- [T3 Code](https://github.com/pingdotgg/t3code) ([Website](https://t3.codes/), [V2 release](https://github.com/pingdotgg/t3code/releases/tag/v0.1.0)) - MIT-licensed coding-agent control plane with cross-provider child-task delegation, visible lineage, MCP thread coordination, and worktree handoffs. Provider-plan access does not establish native dot, Space, or complete Claude Artifacts parity.
- [apowerb](https://github.com/apowerb/apowerb) ([Docs](https://docs.apowerb.com)) - Apache-2.0 self-hosted platform where agents are defined in a web UI or REST API and run on ADK with any model through LiteLLM: single, sequential, parallel or loop agents, with retrieval, Text-to-SQL and MCP tools, triggered on demand, by email or on a schedule, and metered against token quotas with a per-session audit log. Runs with Docker Compose or Helm; a few add-ons such as billing and identity-provider sign-in are sold separately.
- [SpaceApp](https://spaceapp.dev/) ([GitHub](https://github.com/oll4com/spaceapp), [Docs](https://github.com/oll4com/spaceapp/tree/main/docs)) - Source-available (BSL 1.1), self-hosted web workspace where OpenCode, Codex, Claude Code, Gemini CLI, and other coding-agent CLIs run side by side as terminal panes in persistent rooms, with MCP servers, managed browser panes, a Room Agent for coordinating work across panes, and a one-command Docker installer (`npx run-spaceapp`) for Linux, macOS, and Windows 11.
- [Alchemist Coder](https://github.com/Alekla0126/alchemist-coder) ([Website](https://coder.alekla.com), [README](https://github.com/Alekla0126/alchemist-coder/blob/main/README.md)) - AGPL-3.0 desktop app for macOS, Windows, and Linux that runs Claude Code and Codex over the Agent Client Protocol with a live tree of agents and subagents, inline permissions and diffs, an Arena where one to four agents solve the same approved plan in separate git worktrees before you merge one, and a standing coordinator that hands assignments to an organization of agents. Also indexes Claude Code, Codex, Gemini CLI, and Grok Build history into a read-only local search. The free Community edition runs agents only on local models (Ollama, LM Studio); builds are not code-signed yet.
- [Brow](https://github.com/efim0v/brow) ([Website](https://efimov.page/brow/)) - GPL-3.0 macOS app for running parallel Claude Code sessions on a multi-repo project: its menu-bar Workspaces gives each feature one folder holding a git worktree of every chosen repository, all on one branch, and moves a session to another Claude account, while the MacBook notch shows every account's 5-hour and weekly limits. Requires macOS 26+ on Apple silicon.
- [SuperAgent](https://github.com/pungme/superagent-desktop) ([Website](https://superagent.computer/), [Releases](https://github.com/pungme/superagent-desktop/releases)) - MIT-licensed macOS workspace where Claude Code and Codex run as per-project chats, each on its own git worktree, with a real browser the agent drives on the user's existing logins, a dedicated iOS Simulator per chat for build-install-screenshot loops, scheduled routines, and an iPhone companion paired over an end-to-end encrypted relay for approving tool calls remotely.
- [AIWorks](https://github.com/netbka/aiworks) ([README](https://github.com/netbka/aiworks/blob/main/README.md), [Runbook](https://github.com/netbka/aiworks/blob/main/docs/SUPERVISOR.md)) - MIT-licensed supervisor for one Windows PC that runs Claude Code, Codex, and Cursor through an approved plan in isolated git worktrees, has a separate session verify each step, and delivers pull requests to GitHub; it keeps going through crashes, restarts, and usage limits and asks the owner only for decisions. Early preview; real worker execution is Windows-only, and the synthetic-data dashboard demo also runs on Linux and macOS.
- [Tale](https://github.com/tale-project/tale) ([Project agents](https://docs.tale.dev/platform/projects/project-agents), [Harnesses](https://docs.tale.dev/platform/agents/harnesses)) - MIT-licensed project workspace for assigning tasks to reusable AI agents, running coding harnesses in persistent sandboxes, and reviewing reports and deliverables; delegation and review require explicit permissions.
- [Crewly](https://github.com/stevehuang0115/crewly) ([Website](https://crewlyai.com/)) - MIT-licensed local platform that runs a team of role-based agents (developer, QA, PM, orchestrator) on Claude Code, Codex, and Gemini CLI, with task delegation through agent skills, shared persistent memory, and a web dashboard of live agent terminals. OpenCode also works. Requires one of these agent CLIs installed and logged in.
- [Agentastic.dev](https://www.agentastic.dev/) ([Docs](https://www.agentastic.dev/docs)) - Closed-source, free native macOS workspace where Claude Code, Codex, Gemini CLI, and other coding-agent CLIs run in parallel, each task in its own git worktree with a terminal, browser, and diff review, plus optional container, SSH-host, or cloud-sandbox isolation and Manager Agents that start and steer other agents through the dev CLI.
- [AgenticOS](https://github.com/vstorm-co/agenticos) ([Docs](https://vstorm-co.github.io/agenticos/)) - Apache-2.0 self-hosted platform where a company builds, shares and governs its agents in the browser: agents can delegate to other agents, start on schedules or events, answer in web chat, Slack or the API, and each run is checked against budgets and approval rules and kept in an audit log. Built on Pydantic AI; runs with Docker Compose.
- [Scion](https://github.com/GoogleCloudPlatform/scion) ([README](https://github.com/GoogleCloudPlatform/scion/blob/main/README.md)) - Apache-2.0 orchestration for parallel Claude Code, Gemini CLI, Codex, and OpenCode teams with delegation, messaging, and shared workspaces, worktrees, or clones. Pre-1.0; not an officially supported Google product; team behavior depends on supplied instructions.
- [OpenRig](https://github.com/mvschwarz/openrig) ([README](https://github.com/mvschwarz/openrig/blob/main/README.md)) - Apache-2.0 local team coordination through YAML RigSpecs, native coding agents in tmux, messaging, and topology snapshot/restore. Requires Node.js 22 or 24 and tmux on macOS/Linux; setup/startup can write provider hooks and trust settings beyond what dry-run previews.
- [ccswarm](https://github.com/nwiizo/ccswarm) ([README](https://github.com/nwiizo/ccswarm/blob/master/README.md)) - MIT-licensed Rust Sangha workflow engine for Claude Code and Codex planning, quorum assessment, parallel implementation, review, and fixes. Approval markers do not prove required checks; Codex readonly review currently uses workspace-write, replay re-executes, and undo only reports commits.
- [Ruflo](https://github.com/ruvnet/ruflo) ([Swarm plugin docs](https://github.com/ruvnet/ruflo/blob/main/plugins/ruflo-swarm/README.md)) - MIT-licensed coding-agent meta-harness, formerly Claude Flow, for coordinated Claude Code and Codex swarms with team topologies, messaging, and per-agent worktrees. Lite plugins differ from full CLI initialization, which writes configuration/hooks and registers MCP; swarm plugin compatibility and early-access hook requirements apply.
- [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) ([Workflow samples](https://github.com/microsoft/agent-framework/blob/main/python/samples/03-workflows/README.md)) - MIT-licensed Python/.NET developer framework for sequential, concurrent, handoff, and group-collaboration workflows with streaming, checkpoints, and human input. Developers implement and test the application and configure providers; not a ready-made parallel coding-agent workspace.
- [LangGraph](https://github.com/langchain-ai/langgraph) ([Multi-agent docs](https://docs.langchain.com/oss/python/langchain/multi-agent)) - MIT-licensed low-level orchestration framework for durable, stateful agents and custom multi-agent graph composition. Also supports single-agent workflows; not an out-of-box coding-team runner, and optional LangSmith services are separate from the open-source core.
- [solveathome](https://solveathome.org) ([GitHub](https://github.com/solveathome/platform), [Data dumps](https://solveathome.org/dumps)) - MIT-licensed open platform where people set research directions on open problems, their own AI agents (Claude Code, Codex, or anything that can fetch a URL) do the research on their own machines, other contributors' agents check the results, and trusted human reviewers accept or reject them, one vote per person; every result, review, and transcript is public.
- [Coven](https://opencoven.ai/) ([GitHub](https://github.com/OpenCoven/coven), [Docs](https://docs.opencoven.ai/)) - MIT-licensed local-first Rust daemon and CLI that runs Codex, Claude Code, and other coding-agent harnesses as PTY sessions inside explicit project-root boundaries, with SQLite-persisted history and a versioned local socket API.
- [Raven](https://raven.evermind.ai) ([GitHub](https://github.com/EverMind-AI/Raven), [Docs](https://evermind-ai.github.io/Raven/)) - Apache-2.0 host agent that plans complex tasks as DAGs and orchestrates built-in research, coding, design, and on-call agents plus 13 third-party agent presets, including Claude Code, Codex, OpenClaw, and Hermes Agent, over ACP, CLI, or OpenAI-compatible APIs.
- [agent-manager](https://agent-manager.dev/) ([GitHub](https://github.com/YoanWai/agent-manager)) - Apache-2.0 terminal UI for macOS and Linux (Windows via WSL2) where Claude Code, Codex, OpenCode, Gemini CLI, and other coding-agent CLIs run side by side in persistent tmux sessions, with live status, prompts sent without attaching, optional per-session Git worktrees, and diff review that sends line comments back to the agent.
- [Orbi](https://orbi.build/?ref=dir-openorchestrators) ([GitHub](https://github.com/orbi-build/orbi), [Docs](https://docs.orbi.build/)) - AGPL-3.0 self-hosted issue-to-release runner: label a GitHub Issue ai-ready, an agent implements it in an isolated worktree, a separate review session checks the PR against the Issue's acceptance criteria, and only the reviewed head is merged and tagged.
- [workkit](https://github.com/ITW-Creative-Works/workkit) - Claude Code plugin where a manager agent runs GitHub Issues as the work queue, dispatching scout, worker and verifier subagents per issue and parking results for human QA.
- [Bunkhouse](https://github.com/braedonsaunders/bunkhouse) - AGPL-3.0 AI employees for main-street business with a company inbox, org chart, and governed procedures.
- [LoopTroop](https://www.looptroop.ovh/) ([GitHub](https://github.com/looptroop-ai/LoopTroop), [Docs](https://www.looptroop.ovh/docs/)) - MIT-licensed local GUI orchestrator for repo-scale coding tickets: multi-model council planning, atomic milestone decomposition, isolated OpenCode worktrees, fresh-context recovery loops, and human approval gates.
- [GraphCode](https://graphcode.app/) ([GitHub](https://github.com/scgopi/GraphCode), [Releases](https://github.com/scgopi/GraphCode/releases)) - FSL-1.1-MIT native macOS workspace that arranges coding-agent sessions into a graph, where every node is a live terminal and hand-off, message, and spawn edges fire unattended when a goal-based loop's shell predicate exits 0.
- [Crewplane](https://github.com/crewplaneai/crewplane) ([GitHub](https://github.com/crewplaneai/crewplane), [Docs](https://github.com/crewplaneai/crewplane/tree/master/docs)) - Apache-2.0 orchestrator that turns Claude Code, Codex, Gemini CLI, Copilot CLI, and other command-line agents into structured, repeatable Markdown workflows with resumable execution and inspectable local run records.
- [Agon](https://github.com/AutoResearch-Factory/Agon) ([Paper](https://arxiv.org/abs/2606.24177)) - Autonomous research system that coordinates scientist, coder, and auditor loops from topic to idea, proposal, experiment, and paper.

- [Helmor](https://helmor.ai/) ([GitHub](https://github.com/dohooo/helmor), [Releases](https://github.com/dohooo/helmor/releases)) - Apache-2.0 local-first IDE and workbench for orchestrating Claude Code, Codex, and other coding agents across worktrees through planning, running, review, testing, merge, and shipping loops.

## News

Open Orchestrators is also a lightweight news site for meaningful updates from projects already in the directory.

- Add news posts as Markdown files in [`src/content/news`](./src/content/news).
- Set `playerSlug` to the matching entry in [`src/data/orchestrators.ts`](./src/data/orchestrators.ts).
- Include `sourceName` and `sourceUrl` when the post is based on an official announcement, docs page, or repository update.
- The homepage renders the latest story alongside the directory; `/news/` is the full archive.

## Contributing

Before submitting a pull request, please star this repository.

Pull requests are welcome if the project clearly fits the directory scope.

- New submissions must have at least 10 stars on the project's public GitHub repository at review time and a functioning, dedicated project website on its own/custom domain. A GitHub-only presence (including a repository, README, or `github.io` site without a custom domain) does not qualify; include both links in the submission.
- For closed-source products, an official public project, SDK, or integration repository may satisfy the star requirement; product source disclosure is not required. These requirements apply to new submissions and do not retroactively remove existing listings.
- Listing submissions only need to add or update a bullet in the appropriate README category; new projects may also appear in Latest Additions.
- Prefer official website, docs, and GitHub links.
- Keep summaries factual, concise, and based on public sources.
- For governance and enforcement entries, state whether the source is open source, open-core, commercial, or a platform feature.
- If you add a project, include the source you used to verify it.

Maintainers handle website data and validation separately. Contributors do not need to edit `src/data/orchestrators.ts`, install dependencies, run website tests, or preview the website locally for a listing submission.

See [`CONTRIBUTING.md`](./CONTRIBUTING.md) for the full review criteria.

## Local Development

This repo contains the Awesome Multi-Agent Orchestrators list and a small Astro site for [`openorchestrators.org`](https://openorchestrators.org/).

```bash
cd open-orchestrators.org
npm install
npm run dev
```

Maintainers keep the website data in [`src/data/orchestrators.ts`](./src/data/orchestrators.ts), which controls website directory entries, rank order, notes, tags, and links. README-only listing contributions do not require website changes.

News updates should happen in [`src/content/news`](./src/content/news). Directory entries and news posts are intentionally separate: directory metadata describes the player; news Markdown describes a dated update about that player.
